# MA3 MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One grandMA3 Lua plugin that serves MCP over HTTP on the console's production-network address, giving any client full read access to the showfile and gated write access, with a window for PIN, on/off and clients.

**Architecture:** Pure Lua modules under `src/` (HTTP parser, non-blocking socket server, MCP JSON-RPC dispatcher, auth, settings, address validator, tools) are unit-tested on the Mac with Lua 5.4 and a fake console; a build script bundles them into one `MA3 MCP.lua` + `.xml` that the console loads. Inside the console, the server loop runs as a `Timer` task and the window loop as the plugin's `Main`, both yielding every pass.

**Tech Stack:** Lua 5.4 (console) / Homebrew `lua@5.4` (tests); LuaSocket and rxi `json.lua` as shipped inside grandMA3 2.5.1 (vendored copies for tests only); plain-Lua test runner; grandMA3 onPC 2.5.1 on Aaron's Mac as the bench; the grandMA3 light at 10.11.3.10 as the target.

**Spec:** `docs/superpowers/specs/2026-11-03-ma3-mcp-design.md` (read it first; §7 holds every fixed value, §9 the hazards, §12 the captured client flows).

## Global Constraints

- Console target: grandMA3 light, software 2.5.1.1, address 10.11.3.10, port 9800, path `/mcp`.
- The plugin binds the production-network address on the console and `127.0.0.1` on onPC. Never `*` on the console.
- No blocking socket call anywhere: every socket `settimeout(0)`; every loop pass ends with `coroutine.yield()`.
- Never pass `Thru`, `+` or `*` on `Page`/`Executor` to `ObjectList` (hangs 2.5.1). Refuse with `[unsafe-range]`.
- Mutating commands the plugin issues itself carry `/NoConfirmation`; `SaveShow` goes through `CmdIndirect`.
- Show-file names: stem cut to 16 characters; whole backup name ≤ 31 characters; the plugin never deletes show files.
- PIN: 8 characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`; sent as `Authorization: Bearer <PIN>`; wrong PIN → HTTP 401; 5 bad PINs from one IP within 60 s → that IP ignored for 300 s.
- `Origin` header present and not equal to `http://<bind-address>:<port>` → HTTP 403.
- Request budget 10 s default; body limit 1 MB (413 above); response limit 4 MB; bulk reads page at 500 rows with `next_offset`.
- Lua tool: off at every start; sandbox removes `os.exit`, `os.execute`, `os.remove`, `os.rename`, `io`.
- Headers are matched case-insensitively. The bundle uses no MA string extensions (`string.split`) and no library not shipped in the console.
- No secrets in the repo: the PIN lives in the console's settings file; client configs with the PIN live in Claude Code user scope or OneDrive.
- Repo standards: MIT `LICENSE`, `README.md`, `CREDITS.md`, `SECURITY.md`, `.gitignore`, `docs/images/`.
- Aaron installs on and runs anything against the production console; Claude never does without his word.

## Review Focus

1. A request whose headers and body arrive in separate TCP reads, or whose body arrives over several passes: the server must assemble it across yields and never answer 400 early. Test in Task 5 (`server_assembles_split_request`).
2. A client that connects and sends nothing, or disconnects mid-request, while another client is waiting: the first must be dropped on its idle timeout and the second served. Test in Task 5 (`server_drops_idle_client_and_serves_next`).
3. An object address with a quoted name containing spaces and punctuation (`Sequence "Song 2 (Key of D)"`): the validator must accept it and only ranges on Page/Executor are refused. Test in Task 7 (`addr_accepts_quoted_names`).
4. A bulk read that cannot finish inside its budget on a large show: the tool returns the rows it has plus `next_offset`, never an error, and the next call resumes. Test in Task 8 (`fixtures_returns_partial_with_next_offset_on_budget`).
5. A client that speaks only the legacy `initialize` flow, and one that speaks only `server/discover`, each must get a working `tools/call`. Tests in Task 4 (`mcp_legacy_flow_end_to_end`, `mcp_discover_flow_end_to_end`).

### Task 5: Non-blocking socket server

**Files:**
- Create: `src/server.lua`, `test/fake_socket.lua`
- Test: `test/server_test.lua`, `test/server_live_test.lua` (real LuaSocket, loopback)

**Interfaces:**
- Consumes: `http.parse`, `http.response`.
- Produces: `server.new(opts) -> srv`, `opts = {bind, port, socket = require("socket"), now = socket.gettime, handler = function(req, peer_ip) -> status, headers, body, idle_timeout = 5, log = function(fmt, ...) end}`; `srv:start() -> ok, err` (bind + listen, `settimeout(0)`); `srv:step()` (one pass: accept at most 4 new clients, read what is available from each, parse, call `handler` for the oldest complete request only, write pending output, close finished or idle clients); `srv:stop()`; `srv.stats = {requests, bad_requests, clients_now}`; `srv:address() -> ip, port`.
- `step()` never blocks and never calls the handler more than once per pass; it records `srv.last_step = now()` at the end of every pass. A handler may `coroutine.yield()` internally (bulk tools do); the pass then spans frames, which is intended.
